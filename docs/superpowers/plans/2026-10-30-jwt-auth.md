# JWT Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Proteger `/api/*` con JWT en cookie `httpOnly`, dejando públicos `GET /health`, el registro y el login.

**Architecture:** El registro hashea la password y crea el usuario, sin abrir sesión. El login valida contra la tabla `users` con bcryptjs, firma un JWT y lo setea en cookie. Un middleware verifica la firma en cada request. No hay estado de sesión ni consulta a la base por request.

**Tech Stack:** Node.js 24, Express 5, Sequelize 6, MySQL, bcryptjs, jsonwebtoken, cookie-parser, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-30-jwt-auth-design.md`

## Global Constraints

- No agregar dependencias fuera de `jsonwebtoken` y `cookie-parser`; quitar `jwt` y `node-base64`.
- `PasswordHash` nunca debe aparecer en una respuesta HTTP.
- No modificar tablas de Northwind; solo agregar `users` al dump.
- Cookie `httpOnly`, `sameSite=strict`, `secure` solo en producción.
- No consultar la base en `requireAuth`.
- El proyecto no usa migraciones: el dump SQL es la fuente de verdad.
- Los tests requieren MySQL y `.env` con `JWT_SECRET`, `JWT_EXPIRES_IN_SECONDS` y credenciales de base.

## Review Focus

- Usuario inactivo: no debe poder loguearse aunque la password sea correcta.
- Usuario inexistente: misma respuesta 401 que password incorrecta, sin filtrar existencia.
- `PasswordHash` no debe filtrarse en login ni en el modelo por defecto.
- Cookie `secure` no debe romper el login en desarrollo HTTP.
- Token vencido, firmado con otro secreto o con formato inválido → 401, nunca 500.
- `/health` debe responder sin cookie y sin tocar la base.
- El registro debe ser público, no auto-loguear y devolver 201 sin `PasswordHash`.
- Duplicados de username/email (incluida la carrera) → 409; validaciones → 400.
- La password debe quedar hasheada con bcrypt y respetar el máximo de 72 bytes.

cookie (401), token inválido (401), token vencido (401), logout (204 y cookie

- [ ] **Step 2: Verificar que fallan**

Run: `node --env-file-if-exists=.env --test test/auth.test.js`

- [ ] **Step 3: Implementar**

- `src/config/auth.js`: `JWT_SECRET` obligatorio, `JWT_EXPIRES_IN_SECONDS`
  entero positivo (segundos), `SESSION_COOKIE_NAME = 'access_token'`,

  borra la cookie.
- `src/routes/auth.routes.js`.
